# Lev Maltsev Workspace

Локальный веб-инструментарий на HTML/CSS/JS с Python-сервером.

## Возможности

- **YT Observer**: выбор `jupiter` / `saturn` / `miranda`, просмотр таблиц и папок, оценка числа строк, репликация, атрибуты, ключи и схема в friendly/YSON/JSON. Для папок показывается список непосредственно вложенных таблиц.
- **YT Creator**: создание статических, динамических и replicated-таблиц, а также цепочек директорий; пошаговая проверка путей, параметры хранения и визуальный/JSON/YSON-редактор схемы. Proxy формируется как `<cluster>.yt.vk.team`.
- **YT Manager**: изменение storage-атрибутов, создание ссылок, копирование и перемещение нод, mount/unmount dynamic-таблиц, управление replicated table tracker и отдельными репликами. Удаление выполняется по предварительному плану с двойным подтверждением; dynamic-таблицы автоматически отмонтируются, а replicated-структуры удаляются вместе с метаданными и физическими репликами.
- **YT Mutator**: безопасный альтеринг схемы и работа со строками dynamic-таблиц. Поддерживает управление `strict` для статических таблиц, матрицу безопасных изменений типов и optional, предварительный план, проверку schema hash, автоматический unmount/mount, типизированные фильтры, собственный WHERE, пакетное редактирование/удаление и отдельный конструктор новых записей с повторной проверкой ключей.
- **Jira Creator**: конструктор задач UCP с сохраняемыми подпроектами и видами задач,
  поиском Epic Link, плановыми датами, блоком эксперимента и предпросмотром Jira-разметки.
- **Заметки**: rich-text редактор, заголовки, стили, списки, ссылки, картинки, сворачиваемые блоки, автосохранение, черновики, публикация, редактирование и удаление.
- **Токены**: YT/Git/Jira-токены сохраняются в `localStorage` текущего браузера и никогда не возвращаются интерфейсом после установки.
- **Файловое хранение**: заметки лежат в `data/notes/drafts` и `data/notes/articles`, картинки — в `data/notes/uploads`.

## Структура серверной части

`server.py` — точка входа: создаёт Flask-приложение и запускает сервер.
Код приложения находится в пакете `workspace/`:

- `__init__.py` — фабрика `create_app()` и регистрация Flask Blueprints.
- `config.py` — пути хранения, ограничения и поддерживаемые параметры YT.
- `common.py` — разбор JSON-запросов и логирование.
- `web.py` — раздача интерфейса, health check и защитные HTTP-заголовки.
- `notes.py` — файловое хранение заметок и маршруты работы с ними.
- `routes/` — HTTP-маршруты Observer, Creator, Manager и Mutator.
- `routes/jira.py`, `jira/` — маршруты Jira Creator, REST-клиент, сборка задачи и хранение вариантов.
- `yt/` — логика инструментов без HTTP-маршрутов: `observer.py`, `creator.py`,
  `manager.py`, `mutator_schema.py`, `mutator_data.py`; `common.py` содержит
  создание YT-клиента, общие ошибки и преобразования значений.

Зависимости направлены от HTTP-маршрутов к логике YT. Модули приложения
не импортируют `server.py`; для тестов можно создать приложение через `create_app()`.

## Запуск

Самый простой способ — одним скриптом:

```bash
./run.sh
```

Скрипт сам создаст `.venv`, установит зависимости, подготовит папки заметок и запустит сервер на <http://127.0.0.1:1700> **в фоновом режиме через `nohup`**. После запуска терминал можно закрыть.

Если файл потерял executable-флаг после копирования:

```bash
chmod +x run.sh
./run.sh
```

Для доступа с других устройств можно переопределить host:

```bash
HOST=0.0.0.0 ./run.sh
```

Порт при этом остаётся `1700`.

Управление сервером:

```bash
./run.sh status   # проверить состояние
./run.sh logs     # смотреть лог; Ctrl+C закрывает только просмотр лога
./run.sh restart  # перезапустить
./run.sh stop     # остановить
```

PID хранится в `.run/dev-toolbox.pid`, а вывод сервера — в `.run/server.log`.
Закрытие терминала сервер не останавливает. После перезагрузки компьютера его нужно запустить повторно командой `./run.sh`.

## Jira Creator

Откройте «Инструменты → Jira Creator» (`/tools/jira-creator`). В «Настройках»
задайте персональный Jira-токен (PAT), затем нажмите «Подключить».
Используется Jira Server/Data Center REST API v2 с Bearer-авторизацией
и гранулярным `createmeta` (Jira 9+), как в корпоративной MCP-интеграции.
Для доступа к корпоративной Jira может требоваться VPN.

- По умолчанию выбран проект **UCP**, адрес — `https://jira.vk.team`.
  Тип задачи выбирается из доступных в проекте; по умолчанию — Task/Задача, если он есть.
- Исполнитель всегда **Мальцев Лев**, Jira username — `lev.maltsev@mail.msk`.
  Передать другого исполнителя через форму или API нельзя.
- Название обязательно. Подпроект и вид задачи составляют префикс
  `[Подпроект] | Вид задачи | Название`; пустые части пропускаются.
  «Вид задачи» в префиксе не меняет отдельное поле «Тип задачи в Jira».
- Варианты можно добавлять и удалять под соответствующими списками.
  Они сохраняются атомарно в `data/jira/options.json`; начальные варианты — Greenline и Релиз.
- Planned Start по умолчанию — текущая локальная дата в браузере. Обе даты можно очистить.
  Planned End не может быть раньше Planned Start.
- Epic Link ищется по названию среди эпиков выбранного проекта или по точному ключу,
  в том числе другого проекта. Ссылка устанавливается в том же запросе, что создаёт задачу.
- Режим эксперимента: аудитория от 0 (не включительно) до 100%, 1–26 групп (A–Z), слой
  и редактируемые описания групп. В A по умолчанию «контроль».
  Общая аудитория делится поровну; каждая доля округляется до сотых, конечные нули убираются.
  Например, 20% на четыре группы даёт `5x5x5x5`, 20% на три — `6.67x6.67x6.67`.
  После `{noformat}`-блока и `----` добавляется обычное описание.
- Метаданные полей, включая Planned Start/End и Epic Link, загружаются из Jira.
  Дополнительные обязательные поля без значений по умолчанию показываются в форме;
  поддерживаются списки, текст, числа и даты. Неподдерживаемые поля не заполняются догадками.
- После создания отображается ссылка на задачу. Повторная отправка неизменённой формы
  блокируется; при неопределённом результате запроса сначала нужно проверить Jira.
  Черновик и результат сохраняются в `sessionStorage` вкладки.

Токен хранится в `localStorage` браузера и передаётся Flask в `X-Jira-Token`.
Сервер не записывает его в файлы и не возвращает в ответах.
Для запуска без браузерного токена можно передать `JIRA_TOKEN` через окружение процесса;
`JIRA_URL` позволяет переопределить HTTPS-адрес сервера. Перенаправления при запросах
к Jira не выполняются. Файлы вариантов не содержат учётных данных.

## Замена аватара

Откройте «Настройки» → «Фотография» → «Выбрать». Фотография сохраняется в текущем браузере.

## Важное про токены

Python-сервер не сохраняет токены. Браузер передает YT-токен в заголовке `X-YT-Token` только при запросе к YT. Не запускайте сервер с `DEBUG=true` в общей среде и не добавляйте логирование заголовков запросов.
